## A. 보호자 플로우 1 — 가입부터 예약 요청까지 (MVP 대상)

흐름: 메인 → 회원가입 → 로그인 → 반려동물 프로필 → 병원 검색 → 병원 상세 → 결제수단 등록 → 예약 시간 선택.

1. **메인 화면** — 히어로 문구("오늘은 몽이가 어디가 불편한가요?"), 증상/병원명 검색 입력 + 검색 버튼(AI 상담 진입). 하단 "내 주변 추천 병원" 카드 3개(병원명·구·진료역량 태그·예약 가능 여부).
2. **회원가입** — 보호자 가입. 이름·전화번호·이메일·비밀번호. 전화번호는 `010-1234-5678` 형식의 휴대폰 번호를 입력한다. [가입하기]. 하단 "이미 계정이 있나요? 로그인". → `POST /api/auth/signup` (실연동 가능).
3. **로그인** — 이메일·비밀번호. [로그인]. → `POST /api/auth/login` (실연동 가능). 로그인 후 토큰 저장 + `GET /api/members/me`로 역할(`GUARDIAN`/`HOSPITAL_STAFF`) 조회 → 역할에 따라 가드 라우팅(§C 참고).
4. **반려동물 프로필 등록** — 이름·종(8종)·나이·몸무게(kg)·중성화 여부. [프로필 저장]. 오른쪽에 입력값 미리보기 카드. → 펫 CRUD(`/api/pets`, 실연동). weight는 소수 2자리·정수 3자리 제한. 카드에는 **프로필 사진**(없으면 발자국 아이콘)과 [사진 변경]을 둔다 — 발급(`POST /api/pets/{id}/image/upload-url`) → presigned URL로 직접 PUT → `PATCH /api/pets/{id}`(imageUrl)로 확정하는 3단계이고, 형식(jpeg·png·webp)·용량(5MB)은 발급 전에 화면이 먼저 거른다(PR #193).
5. **병원 검색 결과** — "몽이에게 맞는 병원 N곳", 필터 **드롭다운 3개**(반려동물 = 전체+8종 단일 선택 / 진료 특성 = 야간진료·응급·수술·입원 다중 선택, 선택 개수 표시 / 제휴 여부 = 전체·제휴 병원만), 병원 카드 리스트(병원명·거리·역량 태그·예약 가능·[상세]), 카드를 누르면 그 자리에서 지도 펼침. → `GET /api/hospitals` (실연동). 칩을 한 줄로 나열하던 초기 구현을 드롭다운으로 묶었다(PR #194).
6. **병원 상세** — 병원명, 제휴/온라인 예약 배지, 주소·거리·가장 빠른 진료 가능 시간, 진료역량 태그, 병원 안내, 보호자 후기(별점·건수), **찜 하트**(제휴 여부와 무관, 비로그인은 로그인 안내), 오른쪽 예약 패널 [예약 정보 입력]. → `GET /api/hospitals/{id}` (실연동).
7. **결제수단 등록** — "예약 요청 전 결제수단을 등록합니다". PortOne 빌링키 발급 위젯(카드 원본 저장 안 함). [결제수단 등록 완료]. → `POST /api/payment-methods` (실연동, PortOne V2 실게이트웨이). 목록의 ACTIVE 수단에는 [기본으로 지정](`PATCH /api/payment-methods/{id}/default`)과 "기본" 배지를 두고 기본 수단을 맨 위로 올린다. 예약 요청 패널은 기본 수단을 초기 선택값으로 쓴다(PR #193).
8. **예약 시간 선택** — 날짜, 시간 슬롯 그리드(선택 상태 강조), 예약 요약(병원·펫·날짜·시간), [예약 요청하기]. → `POST /api/reservations { petId, slotId, paymentMethodId }` (실연동). 실패: 프로필 없음 400 / 빌링키 없음 400 / 리드타임 위반 400 / 슬롯 점유됨 409.

## B. 보호자 플로우 2 — 예약 관리와 결제/취소 (MVP 대상)

흐름: 내 예약 → (요청 완료) → (예약 확정) → 내원 처리 → 진료 완료 안내 → 결제 처리 중 → 결제 내역 → 취소.

1. **내 예약(목록)** — 펫별 예약 카드(날짜·병원·시간·상태 배지, [상세 보기]). → 예약 목록/상세(실연동).
2. **예약 요청 완료** — "예약 요청이 접수됐어요. 병원 확인 대기." 상태 REQUESTED·승인 대기, 승인 기한 안내, [예약 상세 보기].
3. **예약 확정** — 상태 CONFIRMED. "방문 전 N시간까지 취소 가능." 결제 상태 PENDING. [예약 취소] → `PATCH /api/reservations/{id}/cancel` (실연동). 진료 시작 전·결제 선기록 전에는 **결제수단 변경** 패널을 함께 노출한다(`PATCH /api/reservations/{id}/payment-method`) — 응답에 현재 결제수단 필드가 없어 "지금 쓰는 카드"는 표시하지 못하고 변경 결과만 알린다. 등록된 수단이 없으면 등록 경로를 안내한다(PR #193).
4. **예약 상세·내원 처리** — 상태 CHECKED_IN. 진행 스텝 표시(1 예약확정 · 2 내원완료 · 3 진료중 · 4 진료완료). 상태는 병원 스태프 화면(§C)이 바꾸므로 보호자 프론트는 **조회·표시만**(폴링/SSE).
5. **진료 완료 안내** — 상태 TREATMENT_COMPLETED. 진료 요약, 결제 상태 PENDING.
6. **결제 처리 중** — "결제를 확인하고 있어요." 결제 상태 PENDING(결과 확인 중), 진료비 금액. 결제 트리거·확정은 병원 스태프 화면(§C)이 수행, 보호자 프론트는 상태 표시만.
7. **진료 완료·결제 내역** — 진료비 금액, 등록 카드 last4, 상태 PAID·OFFLINE_REQUIRED·OFFLINE_PAID·**REFUNDED**(전액 환불 완료 시 `refundedAt` 함께 표시). → 결제 내역(실연동, `PaymentHistoryResponse` 배열).
8. **예약 취소** — 상태 CANCELED. "다른 병원 찾기".

상태 배지 값: 예약 REQUESTED/CONFIRMED/REJECTED/CANCELED/CHECKED_IN/IN_TREATMENT/TREATMENT_COMPLETED/NO_SHOW, 결제 PENDING/PAID/OFFLINE_REQUIRED/OFFLINE_PAID/**REFUNDED**.

9. **관심 병원(`/favorites`)** — 찜한 병원 목록(병원명·제휴/영업 배지·주소·[상세])과 하트로 즉시 해제. 헤더 네비 "관심 병원"과 마이페이지 요약 카드로 진입한다. → `GET /api/members/me/favorite-hospitals`(page 1-base), `PUT`·`DELETE /api/hospitals/{id}/favorite`. **보호자 전용**이다(서버가 `hasRole("GUARDIAN")`로 제한) — 스태프에게는 메뉴·하트·라우트를 모두 감춘다(PR #193).
10. **알림 벨(공통 헤더)** — 배지 숫자는 `GET /api/notifications/unread-count`, 드롭다운에 [모두 읽음](`PATCH /api/notifications/read-all`). 목록은 SSE와 벨을 열 때 갱신하고 주기 폴링은 개수만 한다(PR #193).

## C. 병원 스태프 플로우 (MVP+ 고도화 — 구현 대상)

로그인은 보호자와 **공용**이다(`/auth/login`, 별도 병원 로그인 화면 없음). 로그인 성공 후 `GET /api/members/me`의 `role`이 `HOSPITAL_STAFF`면 `/staff`로 리다이렉트하고, 좌측 사이드바형 전용 레이아웃(예약 관리·진료시간·진료역량·임시휴진)을 쓴다. 이하 화면은 `/api/hospital/**`(`ROLE_HOSPITAL_STAFF`) API를 그대로 소비한다.

1. **운영 대시보드(`/staff`)** — 승인 대기 건수(`GET .../reservations?status=REQUESTED`의 `totalElements`)와 승인 대기 목록을 **날짜별로 묶어** 이른 시간부터 보여준다(PR #194). 정렬은 불러온 페이지 범위 안에서만 유효하다 — 목록 API가 `requestedAt DESC`로 페이지를 자르므로 화면에 그 사실을 문구로 밝힌다. "오늘 예약"·"대기 환자" 같은 날짜 집계 카드는 목록 API에 날짜 필터가 없어 **넣지 않는다**. 미수금(현장 수납 필요) 요약 카드는 코드는 있으나 병원 결제 목록 API(`GET /api/hospital/payments`)가 없어 `HOSPITAL_OPS_BACKEND_READY` 플래그로 꺼둔 상태다.
2. **예약 요청 검토(`/staff/reservations`)** — 상태 탭(요청/확정/내원/진료중/진료완료/노쇼), 목록을 날짜별로 묶어(예정 상태는 이른 시간부터, 이력 상태는 최근부터) 보여주고 내원 시각이 지난 건은 지연 표시, 각 행에 예약자 이력 요약(`reservationHistory`), 요청 탭에서만 [승인]/[거절](사유 모달) 버튼. → approve/reject. 예약 시각은 오프셋 없는 `LocalDateTime`이라 Asia/Seoul 기준으로 해석한다(`lib/seoulTime`).
3. **진료 상태 관리(`/staff/reservations/:id`)** — 현재 상태에 맞는 버튼만 활성화: CONFIRMED→[내원 확인], CHECKED_IN→[진료 시작], IN_TREATMENT→[진료 완료], CONFIRMED→[노쇼 확정](사유 모달), NO_SHOW→[노쇼 정정]. → check-in/start/complete/no-show/restore.
4. **진료비 청구** — 같은 상세 페이지, TREATMENT_COMPLETED 상태에서 금액 입력 폼 노출. [청구]. → `POST .../{id}/payments`. 응답 `status`로 즉시 분기: `PAID`(완료 배지), `OFFLINE_REQUIRED`(현장 수납 유도), `PENDING`(정산 스케줄러가 나중에 확정 — 액션 버튼 없이 "확인 중" 안내 + 새로고침만 제공, 사람이 강제로 바꾸는 API 없음).
5. **환불·예외 처리** — 독립된 목록 화면이 아니라 **예약 상세의 결제 섹션에 통합**한다(병원 전체 예외 결제를 한 번에 반환하는 API가 없음). 결제 상태가 `OFFLINE_REQUIRED`면 [현장 수납 완료] 버튼(`PATCH .../offline-settle`), `PAID`면 [전액 환불] 버튼(사유 입력 모달, `POST .../refund`) — 이미 `REFUNDED`면 버튼 비활성화(멱등 재요청 방지).
6. **진료시간 관리(`/staff/operating-hours`)** — 요일 7행에 진료 구간(하루 여러 구간 가능)·휴무 토글, 아래에 발효일 날짜 선택과 [진료시간 저장]. → `GET/PUT /api/hospital/operating-hours`. 화면이 백엔드와 같은 규칙으로 먼저 검증한다(`features/hospitalOps/operatingHours.ts`) — 시작·종료가 같으면 무효, 종료가 시작보다 이르면 **자정을 넘긴 야간 진료로 유효**, 요일 안에서도 주 경계(일→월)에서도 구간이 겹치면 무효. **휴무 토글은 구간을 파기하지 않는다** — 체크할 때 그 요일 구간을 보관해 두고 풀면 그대로 되살리므로(폼이 살아 있는 동안) 삭제 확인 모달을 두지 않는다. 발효일은 오늘 이후만 가능하고, 슬롯 발행창(오늘+13일) 안이면 그 구간의 슬롯을 **통째로** 새 시간표로 교체한다(슬롯을 골라 남기는 부분 교체가 아니다 — `lockOpenSlotsForReplacement`·`replaceOpenSlots`가 예약된 슬롯을 발견하면 전체를 실패시킨다). 그 기간에 예약이 있으면 **서버가 발효일을 마지막 예약일 다음 날로 밀기** 때문에 저장 후 응답의 `effectiveFrom`을 "확정된 발효일"로 따로 알린다. 유효 스케줄이 아직 없는 병원은 조회가 `HOSPITAL_004`로 실패하지만 저장으로 최초 등록이 가능하므로(초기 스케줄 시드는 제휴 병원만 대상) **그 코드일 때만 빈 주 폼을 열어** 등록 경로를 남긴다. 병원이 영업 중이 아니면 시간표만 저장되고 슬롯 재배치는 일어나지 않는다.
7. **진료역량 관리(`/staff/capabilities`)** — 분류(진료 가능 종·검사·치료·장비)별 체크박스 19개, 선택 요약 배지, [진료역량 저장]. → `GET/PUT /api/hospital/capabilities`. PUT은 **전체 교체**라 체크를 푼 항목은 삭제된다는 것을 문구로 밝힌다. 라벨은 `lib/capabilities.ts`가 한 곳에서 관리하고, 저장된 값은 보호자 병원 검색 필터(`requiredCapabilities`)·병원 상세 태그와 같은 값이다. 폐업(`CLOSED`) 병원은 수정이 거부된다. 프론트 화이트리스트에 없는 값(서버에 먼저 추가된 항목)은 분류 그룹에 못 들어가므로 **"분류 미확인" 그룹에 따로 모아** 체크된 상태로 보여준다 — 그대로 두면 보존되고 체크를 풀면 삭제되므로, 값이 조용히 사라지거나 해제할 방법이 없어지는 일이 없다. 이 화면과 진료시간 화면은 **저장하지 않은 편집이 있으면 이탈을 막는다**(`lib/useUnsavedChangesWarning` — 사이드바·링크 이동은 react-router 7 `useBlocker`, 새로고침·탭 닫기는 `beforeunload`). 임시휴진은 편집 상태가 없어 제외한다.
8. **임시휴진 관리(`/staff/temporary-closures`)** — 영업일 날짜 선택 + [임시휴진 등록]/[임시휴진 취소]. → `POST /api/hospital/temporary-closures`(201) · `DELETE .../{businessDate}`(204). 등록·취소 모두 **내일 이후 날짜만** 가능하고, **예약이 있는 날은 등록이 거부**된다(예약을 강제 취소하지 않는다). 취소 시 발행창(오늘+13일) 안이면 슬롯이 즉시 다시 만들어지고 그 밖은 발행 스케줄러가 도달할 때 반영된다. **목록 조회 API가 없어** 현재 걸린 휴진 전체는 표시하지 못하고, 이번 접속에서 처리한 내역만 보여준다(새로고침하면 사라진다는 안내 포함).

**이번 구현에서 뺀 와이어프레임 요소**: 대시보드 날짜 집계 카드, 예약 카드의 증상/주소증 텍스트(엔티티에 없음), 결제 결과 화면의 `[PAID 처리]`/`[현장 결제 전환]` 수동 버튼(PENDING 강제 전이 API 없음), 독립된 환불·예외 목록 화면, 임시휴진 현황 목록(조회 API 없음), 슬롯 단위 휴진(`/api/hospital/slots*` 미구현), 병원 전체 결제 목록(`GET /api/hospital/payments` 미구현 — 대시보드 미수금 요약 카드가 같은 이유로 꺼져 있다). 필요해지면 백엔드에 별도 이슈로 제안한다.

## 구현 메모

- 상태 배지는 공통 컴포넌트(`<StatusBadge status=... />`)로 두고 색을 상태별로 매핑한다.
- 예약 진행 상태(내원 스텝)는 보호자 화면에서는 조회 결과를 표시만 한다 — 전이는 병원 스태프 화면(§C) 몫.
- 미구현 도메인은 mock으로 화면을 먼저 만들고, 백엔드가 나오면 API 클라이언트 레이어에서 엔드포인트만 교체한다.
