## A. 보호자 플로우 1 — 가입부터 예약 요청까지 (MVP 대상)

흐름: 메인 → 회원가입 → 로그인 → 반려동물 프로필 → 병원 검색 → 병원 상세 → 결제수단 등록 → 예약 시간 선택.

1. **메인 화면** — 히어로 문구("오늘은 몽이가 어디가 불편한가요?"), 증상/병원명 검색 입력 + 검색 버튼(AI 상담 진입). 하단 "내 주변 추천 병원" 카드 3개(병원명·구·진료역량 태그·예약 가능 여부).
2. **회원가입** — 보호자 가입. 이름·이메일·비밀번호. [가입하기]. 하단 "이미 계정이 있나요? 로그인". → `POST /api/auth/signup` (실연동 가능).
3. **로그인** — 이메일·비밀번호. [로그인]. → `POST /api/auth/login` (실연동 가능). 로그인 후 토큰 저장·가드 라우팅.
4. **반려동물 프로필 등록** — 이름·종(DOG/CAT)·생년월일 또는 나이·몸무게(kg)·중성화 여부. [프로필 저장]. 오른쪽에 입력값 미리보기 카드. → 펫 CRUD(`/api/pets`, PR 리뷰 중 → 머지 후 실연동). weight는 소수 2자리·정수 3자리 제한, species는 DOG/CAT 화이트리스트.
5. **병원 검색 결과** — "몽이에게 맞는 병원 N곳", 필터 칩(지역·반경·종·진료역량), 병원 카드 리스트(병원명·거리·역량 태그·예약 가능·[상세]), 오른쪽 지도 영역. → 검색 API(#17) **미구현 → mock**.
6. **병원 상세** — 병원명, 제휴/온라인 예약 배지, 주소·거리·가장 빠른 진료 가능 시간, 진료역량 태그, 병원 안내, 보호자 후기(별점·건수), 오른쪽 예약 패널 [예약 정보 입력]. → `GET /api/hospitals/{id}` (실연동 가능).
7. **결제수단 등록** — "예약 요청 전 결제수단을 등록합니다". 카드번호·유효기간·생년월일 등(빌링키 발급용, 카드 원본 저장 안 함). [결제수단 등록 완료]. → `POST /api/payment-methods` (실연동 가능).
8. **예약 시간 선택** — 날짜, 시간 슬롯 그리드(선택 상태 강조), 예약 요약(병원·펫·날짜·시간), [예약 요청하기]. → `POST /api/reservations { petId, slotId, paymentMethodId }` (실연동 가능). 실패: 프로필 없음 400 / 빌링키 없음 400 / 리드타임 위반 400 / 슬롯 점유됨 409.

## B. 보호자 플로우 2 — 예약 관리와 결제/취소 (MVP 대상, 단 환불 제외)

흐름: 내 예약 → (요청 완료) → (예약 확정) → 내원 처리 → 진료 완료 안내 → 결제 처리 중 → 결제 내역 → 취소.

1. **내 예약(목록)** — 펫별 예약 카드(날짜·병원·시간·상태 배지 CONFIRMED/CANCELED 등, [상세 보기]). → 예약 목록/상세(#46) **미구현 → mock**.
2. **예약 요청 완료** — "예약 요청이 접수됐어요. 병원 확인 대기." 상태 REQUESTED·승인 대기, 승인 기한 안내, [예약 상세 보기].
3. **예약 확정** — 상태 CONFIRMED. "방문 전 N시간까지 취소 가능." 결제 상태 PENDING. [예약 취소] → `PATCH /api/reservations/{id}/cancel` (실연동 가능).
4. **예약 상세·내원 처리** — 상태 CHECKED_IN. 진행 스텝 표시(1 예약확정 · 2 내원완료 · 3 진료중 · 4 진료완료). 상태는 병원 운영 API가 바꾸므로 프론트는 **조회·표시만**(폴링).
5. **진료 완료 안내** — 상태 TREATMENT_COMPLETED. 진료 요약, 결제 상태 PENDING.
6. **결제 처리 중** — "결제를 확인하고 있어요." 결제 상태 PENDING(결과 확인 중), 진료비 금액. 결제 트리거·확정은 서버(병원) 몫, 프론트는 상태 표시.
7. **진료 완료·결제 내역** — 진료비 금액, 등록 카드 last4, 상태 PAID(또는 OFFLINE_PAID). → 결제 내역(#47) **미구현 → mock**. ⚠️ REFUNDED/환불 표기는 **MVP 제외**(SA §4·§9-4) — 화면에서 제외한다.
8. **예약 취소** — 상태 CANCELED. "다른 병원 찾기".

상태 배지 값: 예약 REQUESTED/CONFIRMED/REJECTED/CANCELED/CHECKED_IN/IN_TREATMENT/TREATMENT_COMPLETED/NO_SHOW, 결제 PENDING/PAID/OFFLINE_REQUIRED/OFFLINE_PAID. (환불 상태는 MVP에서 표시하지 않음.)

## C. 병원 스태프 플로우 (MVP 범위 밖 — 참고만)

로그인 → 운영 대시보드 → 예약 요청 검토·승인/거절 → 진료 상태 전이 → 진료비 청구 → 결제 결과 처리 → 예외 처리. **PRD §30·§59에 따라 병원 기능은 프론트 화면 없이 운영 API로만 제공**하므로 MVP에서 구현하지 않는다. 선행 백엔드 #27 완료 후 MVP 이후 확장으로 다룬다.

## 구현 메모

- 상태 배지는 공통 컴포넌트(`<StatusBadge status=... />`)로 두고 색을 상태별로 매핑한다.
- 예약 진행 상태(내원 스텝)는 조회 결과를 표시만 한다 — 전이는 병원 운영 API 몫(MVP에서 프론트는 폴링 조회).
- 미구현 도메인(검색·AI·예약 목록·결제 내역)은 mock으로 화면을 먼저 만들고, 백엔드가 나오면 API 클라이언트 레이어에서 엔드포인트만 교체한다.
