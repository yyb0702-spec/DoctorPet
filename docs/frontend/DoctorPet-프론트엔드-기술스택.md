## 1. 범위

- 프론트엔드는 **보호자(GUARDIAN)·병원 스태프(HOSPITAL_STAFF) 웹 SPA 하나**로 구현한다(모노레포 내 단일 앱, 로그인 공용, 역할 기반 라우팅).
- 대상 화면: 인증(로그인), AI 상담, 병원 검색·상세, 펫 프로필 관리, 결제수단 관리, 예약 요청·취소, 예약·결제 내역(REFUNDED 포함), **병원 스태프 운영 화면**(대시보드·예약 승인/거절·진료 상태 전이·진료비 청구·오프라인 정산·전액 환불).
- 디자인 방향(참고): 밝은 배경 + teal/green 포인트, 카드 기반 레이아웃, 예약·결제 상태 머신과 매칭되는 상태 배지. 와이어프레임은 "느낌" 참고용이며 픽셀 단위로 동일하게 맞추지 않는다.
- **와이어프레임에 있지만 이번 구현에서 뺀 요소**(API가 아직 뒷받침하지 않음, 필요하면 별도 백엔드 이슈로 제안): 대시보드의 날짜 집계형 카드("오늘 예약"·"대기 환자" — 목록 API에 날짜/복수상태 필터 없음), 예약 카드의 증상 텍스트(엔티티에 없음), 결제 결과 화면의 수동 강제 전이 버튼(`PENDING`을 사람이 바꾸는 API 없음), 병원 전체의 통합 예외 결제 목록 화면(그런 조회 API 없음 — 예약 상세에 통합).

## 2. 확정 스택

| 레이어 | 채택 | 근거 |
| --- | --- | --- |
| 프레임워크 | **React + Vite** | 웹 SPA 현업 표준, 빌드 빠름, 팀 경험(Agora) 재사용 |
| 언어 | **TypeScript** | `ApiResponse{code, message, data}`와 다수의 DTO·enum(`PetSpecies`·`ReservationStatus`·`PaymentStatus` 등) 계약을 타입으로 고정해 어긋남을 컴파일 단계에서 차단 |
| 서버 상태 | **TanStack Query (React Query)** | `ApiResponse` 언랩·캐싱·로딩/에러·재요청 표준화. 미구현 API를 mock→실 API로 교체만 하면 됨 |
| HTTP | **axios + 인터셉터** | 401 시 Refresh 토큰 자동 재발급(회전 방식, 이슈 #10) 처리에 적합 |
| 라우팅 | **React Router** | 인증 가드·보호 라우트, 역할 기반 라우트(`GUARDIAN` vs `HOSPITAL_STAFF`) |
| 폼·검증 | **React Hook Form + Zod** | 백엔드 검증(`@Size`·`@Digits`·`@NotNull` 등)을 Zod 스키마로 미러링해 프론트 선검증 |
| 클라이언트 상태 | **Zustand** (필요 최소) | 서버 상태는 Query가 담당, 전역 UI 상태·인증 역할(role)만 가볍게 관리 |
| 스타일링 | **Tailwind CSS + shadcn/ui** | 아래 §3 참고 |
| 테스트·툴 | **Vitest + ESLint + Prettier** | Vite 네이티브, 설정 간단 |

## 3. 스타일링 결정 — Tailwind CSS + shadcn/ui (A안)

- 현업 주류이며 커스텀 자유도가 높아 디자인을 직접 다듬기 좋다.
- shadcn/ui로 접근성 갖춘 기본 컴포넌트를 빠르게 확보하되, 코드를 프로젝트에 복사해 소유하므로 종속성이 얕다.
- (대안이었던 MUI/Ant Design은 기성 컴포넌트로 데모 속도를 높이는 선택지였으나, 완성도·트렌드를 우선해 A안을 채택.)

## 4. 백엔드 연동 전제

- **CORS**: 현재 `SecurityConfig`에 `.cors(...)` 설정이 없어 다른 오리진의 프론트는 브라우저에서 차단된다. 프론트 실연동 전에 CORS 허용 설정을 추가해야 한다.
- **API 문서(선택·권장)**: `springdoc(OpenAPI)`가 도입됐다(PR #104, `local` 프로파일 `/swagger-ui`). 이 계약으로 프론트 TS 타입을 자동 생성(`openapi-typescript`)할 수 있어 병렬 작업이 매끄러워진다.
- **역할 판별**: 로그인 응답(`LoginResponse`)에는 role이 없다. 로그인 후 항상 `GET /api/members/me`(`MemberResponse{role,hospitalId}`)로 역할을 조회해 `GUARDIAN`/`HOSPITAL_STAFF`를 구분한다.

## 5. 실시간(push) — SSE 도입(MVP2)

- MVP 알림은 폴링이었다(SA §9-8 v1.35 이전). **MVP2 고도화에서 단방향 SSE로 확정·구현됐다**(티켓 인증 구독, 이벤트명 `notification`, SA §9-8·§8-8, 이슈 #40).
- 알림 조회는 `useNotifications` 훅 하나로 캡슐화되어 있었으므로, 이 원칙을 지켜 **폴링을 완전히 제거하지 않고 SSE를 보조 채널로 하이브리드**한다 — SSE 실패(티켓 만료·연결 상한 429)는 폴링으로 자연 폴백한다.
- 양방향 WebSocket+STOMP는 **병원↔회원 예약 채팅 전용으로 도입·구현됐다**(SA §8-9·§9-12, 백엔드 이슈 #147). 알림 전송은 계속 SSE이며 WebSocket으로 이전하지 않는다. 프론트 채팅 화면(보호자 예약 상세·병원 스태프 예약 상세)은 **PR #159에서 실시간 연동까지 구현됐다** — STOMP CONNECT `Authorization` 헤더로 Access Token을 보낸다(URL 쿼리 파라미터 금지).

## 6. 저장소·배포 및 팀 확인

- **저장소: 모노레포 `frontend/` 채택.** 최종적으로 백엔드 저장소 안 `frontend/` 폴더에 둔다(Agora와 동일 방식).
- **초기에는 로컬 전용으로 작업한다.** 백엔드가 아직 개발 중이고 팀원과 섞이지 않도록, 준비되기 전까지 `frontend/`를 커밋·푸시하지 않는다. 로컬 제외는 `.git/info/exclude`로 처리하며 공유 `.gitignore`는 건드리지 않는다. 안정화되면 exclude를 풀고 커밋해 모노레포에 합류한다.
- 배포 방식은 별도 결정한다. 백엔드 CI(gradle)가 프론트 변경에 도는 낭비는 추후 GitHub Actions `paths:` 필터로 회피한다.
- CORS·springdoc 도입 여부는 백엔드 작업으로 연결된다(§4).
- 위 스택은 결정안이나, 팀 최종 합의 후 이 문서 상태를 유지·갱신한다.
