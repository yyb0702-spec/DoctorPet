## 3.1 예약 대기열 등록 및 자동 승급

### 구현 범위
- 슬롯이 이미 찬 경우 대기열 등록, 동일 사용자·동일 슬롯 중복 등록 차단.
- 대기열 본인 조회·취소.
- 예약 취소·거절·타임아웃으로 슬롯이 반환되면 FIFO 순서로 승급 제안. **제안이 나간 슬롯은 응답 대기 중에도 다른 사용자가 가로챌 수 없다**(아래 "승급 제안 중 슬롯 점유" 참고).
- 승급 제안 수락 시 `REQUESTED` 예약 생성, 제한 시간 내 미응답/거절 시 다음 대기자 승급.
- 승급 상태·이력·알림 저장, 승급 재처리·중복 승급 방지.

### 확정 정책 — 승급 제안 중 슬롯 점유 (STRICT)
- 승급 제안 유효 시간은 **10분**이다.
- 보호자가 제안을 수락하면 신규 예약을 `REQUESTED` 상태로 생성한다.
- `OFFERED` 대기열이 존재하는 동안 슬롯은 `RESERVED`를 유지한다. 따라서 일반 예약 생성 경로는 해당 슬롯을 점유할 수 없다.
- 제안 거절·만료 시 같은 트랜잭션에서 FIFO 다음 대기자에게 즉시 제안한다.
- 더 이상 `WAITING` 대기자가 없을 때만 슬롯을 `OPEN`으로 반환한다.

슬롯 상태는 SA §5-3의 `OPEN`/`RESERVED` 둘만 유지한다. 별도 `HELD` 상태나 `reservation_slots.offered_to_waitlist_id` 컬럼을 추가하지 않는다. 승급 제안 생성·만료·수락은 슬롯의 기존 `@Version` 낙관적 락과 대기열의 `@Version`을 같은 트랜잭션에서 사용해 한 번만 성립시킨다.

### 1단계 데이터 모델
`reservation_waitlists`는 `member_id`, `slot_id`, `status`, `offered_at`, `offer_expires_at`, `responded_at`, `canceled_at`, 감사 시각, `version`을 저장한다.

- `UNIQUE(member_id, slot_id)`으로 동일 보호자·동일 슬롯 중복 등록을 DB에서도 차단한다.
- `(slot_id, status, created_at, id)` 인덱스로 FIFO 후보를 안정적으로 조회한다. 동률은 `id` 오름차순으로 결정한다.
- 테이블 DDL은 `ReservationWaitlistSchemaMigrationRunner`가 Hibernate 초기화 전에 생성·검증하며, `schema_migrations` 마커와 MySQL named lock으로 재실행·다중 인스턴스 실행을 막는다.

### API·만료 처리
- `POST /api/reservation-waitlists`: 마감(`RESERVED`) 슬롯의 대기열 등록.
- `POST /api/reservation-waitlists/{waitlistId}/accept`: 제안 수락. 요청 body의 `petId`, `paymentMethodId`는 수락 시점에 보호자 소유·활성 상태를 다시 검증하고, 유효한 `OFFERED` 대기열만 `ACCEPTED`로 전이한 뒤 새 `REQUESTED` 예약을 생성한다.
- `PATCH /api/reservation-waitlists/{waitlistId}/reject`: 제안 거절. `REJECTED` 전이 후 즉시 FIFO 다음 대기자에게 제안하고, 다음 대기자가 없을 때만 슬롯을 `OPEN`으로 반환한다.
- `ReservationWaitlistExpirationScheduler`는 기본 1분 주기로 만료된 `OFFERED`를 조회한다. 만료 건은 `EXPIRED` 전이 후 같은 슬롯의 다음 FIFO 대기자에게 즉시 제안한다.

수락·거절·만료 모두 대기열의 `@Version`을 flush해 상태 전이 충돌을 즉시 감지한 뒤에만 후속 슬롯 반환 처리를 진행한다. 실제 MySQL 다중 스레드 검증은 §5의 STRICT 테스트로 보장한다.

### 상태 흐름
`ACCEPTED`·`EXPIRED`·`REJECTED`는 모두 `OFFERED`에서만 갈라지는 서로 다른 결과이며, 한쪽으로 전이한 뒤 다른 쪽으로 역전이하지 않는다.
```text
WAITING ──(본인 취소)──────────────→ CANCELED
   │
   │ (슬롯 반환 시 FIFO 승급 제안)
   ▼
OFFERED ──(수락)───────────────────→ ACCEPTED
   │
   ├──(제한 시간 내 미응답)────────→ EXPIRED
   └──(거절)───────────────────────→ REJECTED
```
`CANCELED`는 위 그림에서 `WAITING`에서만 본인 취소로 도달한다. `OFFERED` 상태의 본인 취소 허용 여부는 아직 정해지지 않았으므로 수락·거절 API 구현 단계에서 별도 결정한다.

### 구현 근거
- 슬롯이 마감돼도 보호자가 예약 기회를 가질 수 있게 보완한다.
- 취소·거절·타임아웃으로 빈 슬롯을 방치하지 않고 다음 사용자에게 연결한다.
- 동시에 여러 사용자가 승급되는 상황을 슬롯의 기존 `@Version` 낙관적 락(SA §9-3, AGENTS 확정 결정)과 위 "승급 제안 중 슬롯 점유" 기본안으로 함께 방지한다 — `@Version`만으로는 일반 예약 생성이 제안 대기 중인 슬롯을 가로채는 것까지 막지 못한다.

### 남은 정책 결정
- 대기열 우선순위는 FIFO로 확정하며, 유료 우선권 등 다른 정책은 제외한다.
- 본인 취소(`CANCELED`)는 1단계에서는 `WAITING`만 지원한다. `OFFERED` 상태의 본인 취소 허용 여부는 수락·거절 API 구현 전에 확정한다.

### 제외 범위
- 대기열 우선순위 고도화, SSE·WebSocket 실시간 전송, 결제·환불, 병원 통계·관리자 화면, AI 예약 Tool Calling, 복잡한 보상·재예약 정책.

## 3.2 병원 측 확정 예약 취소

### 구현 범위
- 병원 본인 소유 예약 검증 후 `CONFIRMED` 예약의 병원 취소 API 제공, 취소 사유 필수.
- 병원 취소 전용 상태·이력 저장, 취소된 예약의 체크인·진료 시작·완료 차단.
- 보호자 대상 `RESERVATION_HOSPITAL_CANCELED` 알림 발행.
- 병원 취소 시 슬롯을 `OPEN`으로 반환. 대기열 승급 트리거 연결은 3.1 구현 범위로 분리한다.

병원 취소 상태·컬럼·이벤트·알림·API의 최종 계약은 SA v1.57 §4·§5-1·§5-3·§8-6을 따른다. 기존 `HOSPITAL_CANCELLED` 데이터는 Hibernate `ddl-auto=update`보다 먼저 실행되는 선행 마이그레이션에서 `HOSPITAL_CANCELED`로 변환하고, 애플리케이션 기동 후 사후 검증을 다시 수행한다.

### 상태 흐름
```text
CONFIRMED → HOSPITAL_CANCELED
```
`REQUESTED`·`REJECTED`·`CHECKED_IN`·`IN_TREATMENT`·`TREATMENT_COMPLETED`(실제 `ReservationStatus` enum 이름 — `IN_PROGRESS`·`COMPLETED`는 존재하지 않는다)는 이번 병원 취소 대상에서 제외한다.

### 구현 근거
- 병원 API에 승인·거절·체크인·진료 시작/완료가 있어도, 수의사 질병·응급수술 등으로 확정 예약을 중단하는 전이가 없으면 운영상 예약을 해소할 수 없다.
- 병원 취소와 보호자 취소를 구분해야 취소 주체·알림·통계·후속 대기열 처리를 정확히 구분한다.
- 상태 머신에 허용 전이를 추가하는 범위이며 결제·환불 정책을 새로 정의하지 않는다.

### 제외 범위
- 보호자 취소 정책 변경, 결제 취소·환불·보상·위약금, 취소 사유별 보상 정책, 확정 외 상태의 병원 취소, 대기열 승급 우선순위 정책.

## 4. 구현 의존성·순서

```text
(승인·거절 알림 = develop 완료)
병원 확정 예약 취소 → 슬롯 반환 이벤트
        ↓
대기열 자동 승급 → 승급 알림 + REQUESTED 예약 생성
```

권장 순서: 병원 확정 취소 → 대기열 등록·자동 승급. 대기열은 취소·거절·타임아웃을 트리거로 쓰므로 상태 변경·슬롯 반환 흐름을 먼저 안정화한다.

## 5. 검증 (STRICT: 상태 전이·슬롯 점유·낙관적 락)
- 기능: `CONFIRMED→HOSPITAL_CANCELED` 정상 전이, 타 병원·잘못된 상태 취소 차단, 취소·거절·타임아웃 후 FIFO 승급, 승급 수락 시 `REQUESTED` 생성, 승급 거절·만료 시 다음 대기자.
- 정합성: 승인·거절·취소 중복 요청 방지, 동일 이벤트 재처리 시 예약·이력·알림 중복 생성 방지, 동시 승급에도 1명만 승급, **승급 제안 응답 대기 중인 슬롯을 일반 예약 생성이 가로채지 못함**, 병원 취소 이후 체크인·진료 차단.
- 실행: 대기열 동시성은 실제 MySQL Level 3, 로컬 기동 Level 5, 실제 HTTP Level 6. 판정 PASS만 완료 근거.

## 6. 완료 기준
- 대기열 등록·자동 승급, 병원 확정 취소의 포함 범위가 구현된다.
- 확정 정책(10분 제안, 수락 시 `REQUESTED`, `OFFERED` 중 `RESERVED` 유지)이 이 델타 문서에 반영된다.
- 상태 전이·권한·멱등성·동시성 테스트 통과, 새 상태/전이가 SA §5 상태 머신에 반영된다.
- 병원취소·대기열 알림의 NotificationType·발행 방식이 알림 도메인과 합의돼 반영된다.
- 제외 범위가 섞이지 않는다. PR 리뷰 완료.
