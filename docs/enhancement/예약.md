## 3.1 예약 대기열 등록 및 자동 승급

### 구현 범위
- 슬롯이 이미 찬 경우 대기열 등록, 동일 사용자·동일 슬롯 중복 등록 차단.
- 대기열 본인 조회·취소.
- 예약 취소·거절·타임아웃으로 슬롯이 반환되면 FIFO 순서로 승급 제안.
- 승급 제안 수락 시 `REQUESTED` 예약 생성, 제한 시간 내 미응답/거절 시 다음 대기자 승급.
- 승급 상태·이력·알림 저장, 승급 재처리·중복 승급 방지.

### 상태 흐름
`ACCEPTED`·`EXPIRED`·`REJECTED`는 모두 `OFFERED`에서만 갈라지는 서로 다른 결과이며, 한쪽으로 전이한 뒤 다른 쪽으로 역전이하지 않는다.
```text
WAITING ──(본인 취소)──────────────→ CANCELLED
   │
   │ (슬롯 반환 시 FIFO 승급 제안)
   ▼
OFFERED ──(수락)───────────────────→ ACCEPTED
   │
   ├──(제한 시간 내 미응답)────────→ EXPIRED
   └──(거절)───────────────────────→ REJECTED
```
`CANCELLED`는 위 그림에서 `WAITING`에서만 본인 취소로 도달한다고 그렸다 — `OFFERED` 상태(승급 제안을 받은 뒤 응답 전)에서도 본인 취소가 가능한지는 아직 정해지지 않았다(아래 선행 정책 결정 참고).

### 구현 근거
- 슬롯이 마감돼도 보호자가 예약 기회를 가질 수 있게 보완한다.
- 취소·거절·타임아웃으로 빈 슬롯을 방치하지 않고 다음 사용자에게 연결한다.
- 동시에 여러 사용자가 승급되는 상황을 낙관적 락(`@Version`)으로 방지한다(SA §9-3, AGENTS 확정 결정).

### 선행 정책 결정
- 응답 제한 시간·자동 확정 여부(기본안: 10분 제안 후 수락 시 `REQUESTED` 생성). 확정 전 구현하지 않는다.
- 대기열 우선순위 정책(기본 FIFO, 그 외는 제외).
- 본인 취소(`CANCELLED`)가 `WAITING`에서만 가능한지, `OFFERED`(승급 제안 응답 대기 중)에서도 가능한지. 확정 전 구현하지 않는다.

### 제외 범위
- 대기열 우선순위 고도화, SSE·WebSocket 실시간 전송, 결제·환불, 병원 통계·관리자 화면, AI 예약 Tool Calling, 복잡한 보상·재예약 정책.

## 3.2 병원 측 확정 예약 취소

### 구현 범위
- 병원 본인 소유 예약 검증 후 `CONFIRMED` 예약의 병원 취소 API 제공, 취소 사유 필수.
- 병원 취소 전용 상태·이력 저장, 취소된 예약의 체크인·진료 시작·완료 차단.
- 보호자 대상 병원 취소 알림 발행(→ 알림 도메인과 조율).
- 병원 취소로 슬롯이 반환되면 대기열 승급 트리거 연결(3.1).

### 상태 흐름
```text
CONFIRMED → HOSPITAL_CANCELLED
```
`REQUESTED`·`REJECTED`·`CHECKED_IN`·`IN_PROGRESS`·`COMPLETED`는 이번 병원 취소 대상에서 제외한다.

### 구현 근거
- 병원 API에 승인·거절·체크인·진료 시작/완료가 있어도, 수의사 질병·응급수술 등으로 확정 예약을 중단하는 전이가 없으면 운영상 예약을 해소할 수 없다.
- 병원 취소와 보호자 취소를 구분해야 취소 주체·알림·통계·후속 대기열 처리를 정확히 구분한다.
- 상태 머신에 허용 전이를 추가하는 범위이며 결제·환불 정책을 새로 정의하지 않는다.

### 제외 범위
- 보호자 취소 정책 변경, 결제 취소·환불·보상·위약금, 취소 사유별 보상 정책, 확정 외 상태의 병원 취소, 대기열 승급 우선순위 정책.

## 4. 구현 의존성·순서

```text
(승인·거절 알림 = develop 완료)
병원 확정 예약 취소 → 슬롯 반환 이벤트
        ↓
대기열 자동 승급 → 승급 알림 + REQUESTED 예약 생성
```

권장 순서: 병원 확정 취소 → 대기열 등록·자동 승급. 대기열은 취소·거절·타임아웃을 트리거로 쓰므로 상태 변경·슬롯 반환 흐름을 먼저 안정화한다.

## 5. 검증 (STRICT: 상태 전이·슬롯 점유·낙관적 락)
- 기능: `CONFIRMED→HOSPITAL_CANCELLED` 정상 전이, 타 병원·잘못된 상태 취소 차단, 취소·거절·타임아웃 후 FIFO 승급, 승급 수락 시 `REQUESTED` 생성, 승급 거절·만료 시 다음 대기자.
- 정합성: 승인·거절·취소 중복 요청 방지, 동일 이벤트 재처리 시 예약·이력·알림 중복 생성 방지, 동시 승급에도 1명만 승급, 병원 취소 이후 체크인·진료 차단.
- 실행: 대기열 동시성은 실제 MySQL Level 3, 로컬 기동 Level 5, 실제 HTTP Level 6. 판정 PASS만 완료 근거.

## 6. 완료 기준
- 대기열 등록·자동 승급, 병원 확정 취소의 포함 범위가 구현된다.
- 선행 정책(응답 제한 시간 등)이 구현 전 PRD/SA에 반영된다.
- 상태 전이·권한·멱등성·동시성 테스트 통과, 새 상태/전이가 SA §5 상태 머신에 반영된다.
- 병원취소·대기열 알림의 NotificationType·발행 방식이 알림 도메인과 합의돼 반영된다.
- 제외 범위가 섞이지 않는다. PR 리뷰 완료.
