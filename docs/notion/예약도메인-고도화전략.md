# 예약 도메인 고도화 전략

## 1. 현재 구현 상태

- 보호자 예약 요청 API 구현
- 보호자 예약 취소 API 구현
- 보호자 예약 목록·상세 조회 API 구현
- 예약 슬롯 `OPEN ↔ RESERVED` 처리
- 예약 생성·취소의 트랜잭션 처리
- 예약 4시간 전 요청 제한
- 예약 2시간 전 취소 제한

## 2. 1단계: 도메인 연동 완성 (완료)

현재 예약 요청·취소는 예약 도메인의 상태와 슬롯 정책을 중심으로 동작한다. 다음 단계에서 다른 도메인과 실제 검증을 연결한다.

- 회원 ID와 인증 주체 검증
- 반려동물 소유권·활성 상태 검증
- 결제수단 소유권·활성 상태 검증
- 반려동물 프로필에서 이름·종 스냅샷 자동 생성
- 목록 조회 시 병원·슬롯 일괄 조합

## 3. 2단계: 동시성 및 정합성 강화

- `ReservationSlot.version` 기반 낙관적 락 예외 처리
- 동일 슬롯 동시 예약 통합 테스트
- 예약 저장 실패 시 슬롯 점유가 rollback되는지 검증
- 이미 취소된 예약의 중복 취소 방지
- 예약 슬롯별 활성 예약이 하나만 존재하는지 DB 제약 검토
- 사용자에게 충돌 원인을 일관된 `SLOT_*` 오류 코드로 반환

## 4. 3단계: 병원 운영 흐름 연결

- 병원 직원의 예약 요청 목록 조회
- `REQUESTED → CONFIRMED` 승인
- `REQUESTED → REJECTED` 거절 및 사유 저장
- 승인 응답 데드라인 자동 거절
- 체크인·진료 시작·진료 완료 상태 전이
- 노쇼 자동 판정과 수동 정정 이력 저장

## 5. 4단계: 조회·알림·운영 개선

- 보호자 예약 목록·상세 조회 (완료)
- 상태 변경 알림 및 알림 이력 연결
- 예약 이력·취소 이력·노쇼 이력 조회
- 예약 상태별 운영 통계
- 만료된 예약 요청 정리 스케줄러
- Swagger와 Postman 기반 예약 시나리오 자동화

## 6. 고도화 우선순위

1. 회원·반려동물·병원·결제수단 연동
2. 슬롯 동시성 통합 테스트
3. 병원 승인·거절 흐름
4. 예약 조회·알림
5. 노쇼·통계·운영 자동화

결제 환불, 대기열, 실시간 알림은 예약 요청·취소의 정합성이 확보된 이후 확장한다.
